# Simulation experiment plan: online environment-manifold routing for G1

This is the experiment specification for the current `deploy` branch. It is designed to answer
whether an online 3-D environment manifold can select a dynamically feasible motion primitive,
keep the robot's own measured envelope inside the corridor, and re-route fast enough for a
whole-body controller. It is a simulation plan, not a claim of CVPR acceptance.

## Claims to test

1. A 3-D probability map and route-local ellipsoid `M_e(t)` can select crouch, side-step,
   turn and nominal locomotion from geometry rather than from a route-segment label.
2. Incremental truncated ESDF + D* Lite reduces update latency versus full voxel A* while
   preserving route success and minimum clearance under map changes.
3. Current-state/history-conditioned candidate generation plus projection and a shadow MuJoCo
   gate produces safe semantic switches without a root-position teleport.
4. The measured self-manifold gate predicts collision/near-collision failures better than a
   pelvis-only corridor check.
5. A measured self-manifold gate and state/history-conditioned candidate screen reduce unsafe
   switches compared with a pelvis-only or open-loop reference check.

## Scenarios

Each scene is evaluated over 32 deterministic seeds and 8 held-out geometry seeds. All maps are
3-D voxels (0.08 m resolution, 128x128x32 sliding window) even when the route is ground-bound.

| family | conditions | required behavior |
|---|---|---|
| open | center, wide | nominal walk, no unnecessary semantic switch |
| static narrow | 0.95/0.85/0.75 m corridors, left/right detours | side-on gait, body yaw near corridor tangent |
| static low | 1.20/1.10/1.00/0.90 m overhead clearances | crouch before entering the low interval |
| compound | narrow→low→turn→wide, low→side→wide | keyframe-preserving multi-primitive sequence |
| dynamic | crossing block, appearing/disappearing block, moving side wall | re-route after new radar evidence |
| perturbation | radar dropout/noise, SLAM timestamp skew, extrinsic error | graceful hold/stop and bounded degradation |
| generalization | random box layouts, unseen lengths and heights | no scene-specific segment lookup |

The released moving-obstacle artifact is generated by
`manifold_motion.incremental_dynamic_benchmark` and is accompanied by a GIF and JSON timing
report. The 3-D map and the MuJoCo rollout must be saved for every accepted trial.

## Baselines and ablations

Run every row with the same SONIC weights, candidate budget, physics timestep, seeds and
termination thresholds.

| ID | planner/controller | purpose |
|---|---|---|
| B0 | fixed nominal SONIC + straight route | lower-bound behavior/collision baseline |
| B1 | full 3-D voxel A* + fixed nominal primitive | isolates route planning |
| B2 | full 3-D voxel A* + offline segment primitive | current pre-deploy chain |
| B3 | full 3-D voxel A* + online `M_e` primitive, no history | isolates online geometry |
| Ours-1 | incremental ESDF + D* Lite + online `M_e`, no projection | planner/semantic contribution |
| Ours-2 | + optimization-embedded projection | feasibility contribution |
| Ours-3 | + current-state shadow gate and hysteresis | safe-switch contribution |
| Ours-4 | + state/history-conditioned Flow candidate | full Stage-2 model |
| A0 | Ours-4 without self-manifold gate | tests real-deployment safety layer |
| A1 | Ours-4 without current root/history | tests the root-position/history hypothesis |
| A2 | Ours-4 with route-segment token instead of measured `M_e` | tests environment causality |
| A3 | Ours-4 with random/zero condition residual | condition-adapter sanity check |
The primary paper comparison should be B2, Ours-2, Ours-3 and Ours-4. B0/B1/A0/A2 are
diagnostic ablations. A tabula-rasa controller is intentionally deferred until a matched
controller training budget and stable SONIC replacement interface exist.

## Metrics

### Task and safety

- success rate: final goal and all intermediate keyframes reached;
- collision rate and contact ticks, split into obstacle, hand, non-foot floor;
- minimum exact mesh-to-obstacle clearance and minimum measured self-manifold clearance;
- fall/roll failure, terminal keyframe error and route-deviation P50/P95;
- primitive correctness: fraction of low/narrow intervals classified as crouch/side and false
  switch rate in open space;
- switch latency: first valid radar timestamp to committed primitive, with 95% CI.

### Real-time and control quality

- map update, ESDF update, D* Lite update and complete candidate/shadow-gate latency (P50/P95);
- expanded vertices, changed ESDF cells, route length/optimality gap;
- joint tracking RMS, root tracking error, acceleration/jerk, energy proxy and action saturation;
- route/yaw command age and number of temporary-no-route holds.

### Robustness and generalization

- success/clearance versus radar noise, dropout and SLAM time skew;
- success versus base-to-sensor translational/rotational extrinsic error;
- in-distribution versus held-out obstacle geometry and held-out source origins;
- paired seed-wise difference with bootstrap 95% CI, not only a single best GIF.

## Protocol

1. Fix a public manifest of scene geometry, random seeds and software commit. Generate each
   3-D map from the same geometry but expose scans incrementally to the online method.
2. Warm up SONIC identically, run 50 Hz physics and 2.5 Hz radar unless the ablation changes
   cadence. Save `condition.npz`, voxel maps, route reports, executed state, switches and GIF.
3. Reject a trial if the hard gate stops, a contact occurs, the self-manifold clearance is below
   threshold, or a final keyframe is missed. Never repair a failed reference and relabel it.
4. For each scene/seed, evaluate all methods from the same initial state. Report paired success
   differences, median/P95 latency and clearance distributions. Use a bootstrap over scene-seed
   pairs; use a Wilcoxon signed-rank test only as a secondary summary.
5. Keep train/validation/test split by `source_origin` (not random windows). Transition samples
   retain both source origins and are never allowed to leak a held-out actor/clip into training.
6. Release the exact command lines, configs, reports, NPZ contracts and the synchronized
   MuJoCo+SLAM GIF for representative accepted and failed trials.

## Pilot sanity checks (not final paper statistics)

- The synchronized long-horizon MuJoCo/radar run reaches 11/11 keyframes with zero obstacle
  contacts, 0.152 m route-deviation P95, 0.187 m minimum runtime self-manifold clearance and
  three shadow-gated online semantic commits.
- Across 18 online map updates, D* Lite planning has 50.5 ms median and 65.5 ms P95 latency at
  the current 2.5 Hz radar rate. The separate moving-obstacle benchmark changes route four times
  and has 27.1 ms median incremental latency after initialization versus 2.14 s for full voxel A*.
- The transition supplement contains 192 clips; a representative MuJoCo gate accepts 12/12
  (`walk <-> turn/side/crouch`, two per direction).
- The latest side-on pilot re-runs wide/low/narrow/center with zero obstacle contacts, 6/6 or
  10/10 keyframes, and measured aperture-driven primitive changes. The separate dynamic pilot
  reports 23.16 ms median incremental planning versus 2009.36 ms full voxel A*.

## CVPR-level evaluation governance

The paper table is generated from a frozen plan, not from whichever runs happened to succeed.
Before the first full sweep:

1. Freeze `configs/cvpr_simulation_protocol.json`, the code commit, five independent training
   seeds, all evaluation seeds, scene parameters and every hard threshold.
2. Generate `benchmark_plan.jsonl`. Its SHA-256 and commit become part of the artifact manifest.
3. Run paired methods from the same simulator initial state and sensor-noise stream. A failed or
   timed-out run remains in the result set with a failure category.
4. Audit that every planned `run_id` has exactly one schema-complete result before aggregation.
5. Report all primary metrics and the predefined B2/Ours-2/Ours-3/Ours-4 comparison. Diagnostic
   ablations may not replace the primary table after results are known.

```bash
PYTHONPATH=. python3 -m manifold_motion.cvpr_benchmark plan \
  --out reports/cvpr/benchmark_plan.jsonl
PYTHONPATH=. python3 -m manifold_motion.cvpr_benchmark audit \
  --plan reports/cvpr/benchmark_plan.jsonl --results reports/cvpr/results.jsonl
PYTHONPATH=. python3 -m manifold_motion.cvpr_benchmark summarize \
  --results reports/cvpr/results.jsonl --out reports/cvpr/summary.json
```

The primary evaluation uses 32 paired seeds per scene. Diagnostic ablations use eight seeds to
control compute. Controller learning uses five independent training seeds. Report mean/median as
appropriate, bootstrap 95% confidence intervals, paired method-minus-B2 effects and exact sample
counts. Control the four declared primary metric families with Holm-Bonferroni; do not present
single-seed GIFs as quantitative evidence.

## Required qualitative evidence

The project page/GitHub gallery must contain, for both representative success and failure cases:

- synchronized MuJoCo, 3-D occupancy slices, route, `M_e(t)`, measured `M_r^safe`, selected
  primitive, clearance and hard-gate state;
- an appearing/crossing/disappearing obstacle sequence with old and repaired routes;
- a compound long sequence with at least three primitive changes and no state reset;
- a paired counterfactual with identical initial state/route and changed aperture only;
- one honest failure from each major category: perception stale, planner no route, primitive
  mismatch, projection infeasible, controller tracking failure and self-manifold stop.

Compact GitHub previews are built from accepted raw reports by
`manifold_motion.build_github_demo_gallery`. The source reports, full-resolution videos and JSON
metrics remain downloadable artifacts. Preview generation never changes acceptance labels.

## Reviewer-facing completeness checklist

- Compare against route-only, offline-primitive, online-without-history and no-self-manifold
  baselines; keep the SONIC controller fixed across all primary comparisons.
- Separate perception, planning, generation and controller latency, and report P50/P95 plus GPU
  memory on the named hardware.
- Report training compute, evaluation compute, parameter counts and checkpoint-selection rule.
- Release train/validation/test source provenance and prove that actor/clip/geometry identities do
  not leak across splits.
- Publish accepted and failed run IDs, not only videos; include a failure taxonomy and sensitivity
  curves for clearance threshold, radar rate, D* truncation distance and switch hysteresis.
- State clearly that 3-D voxels determine vertical clearance while D* Lite plans a ground-bound XY
  route; do not describe the route search itself as free-flying 3-D planning.
- Repeat final tables from a clean clone and record exact Git/LFS hashes before submission.
